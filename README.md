# arch-audit-pipeline

**吃透一个项目的架构：⓪ 项目快照 → ①-⑥ 理解与审计 → ⑦ 图表 → ⑧ 双文档** —— ZCode / CodeBuddy 标准 Skill。

> **首要目的是搞清楚架构**：⓪→⑧ 的产物链合起来，让新同事、三个月后的你、或任何 agent 能独立讲清"这系统由什么组成、块与块怎么调、为什么这样设计、哪里有坑"。**架构审计是重要的副目标**（⑤ 硬门 + ⑥ 反幻觉为理解的正确性兜底）——副目标不可跳过、⓪→⑧ 默认全量做完，但每一步产物都为"被理解"而写，不为过关而写。

对既存代码库（或散落多处的项目文件）产出一条可复验的交付物链：

| 阶段 | 步骤 | 产出 |
|---|---|---|
| 前置 | ⓪ 项目搜索与快照打包（**确定性程序**：git index → 包根 → 索引 → import 闭包信号阶梯 + scope-probe 探测双跑一致 + 覆盖率双检） | 只读副本 bundle + `README-BUNDLE.md` + `scope-probe-result.json`（in_scope/out_reference/excluded 三清单） |
| 审计 | ①范围框定 → ②静态制图 → ③分层下钻 → ④架构推断 → ⑤架构审计 → ⑥事实校验 | `AGENTS.md` / `dep-edges.json` / `module-cards/` / `architecture.md` / `audit-report.md` / `facts-checklist.md` |
| 产出 | ⑦图表产出 → ⑧三文档产出 | `7-diagrams/` 图集（全局级+模块级，图即代码）+ 三文档：技术版审计报告 / 大白话教材版 / 草履虫极简版 |

## 核心立场

- **审计是硬性质量门，不是增值项**——只描述现状不评估合理性的架构图，是无法区分主干和肿瘤的解剖图。⑤ 为独立关卡：Critical（循环依赖、分层彻底失效、声明扩展点完全未使用等）未清零，`architecture.md` 不得标记为可交付。
- **⑥ 反幻觉兜底**——报告每条断言必须附 `file:line` 证据；证伪项回写修正后流程才算交付。
- **执行纪律十锁**（与任何步骤指令冲突时以它为准）：
  1. 串行门——上一步产物未落盘不得开始下一步；
  2. 执行日志即证据（含九步状态表）——没有 log 记录的步骤视为未执行，每步收尾心跳 n/9；
  3. 数字必须脚本实算——零结果也要贴"做了哪些检查才判零"；
  4. **沙级颗粒度**——产物按最小可验证单元（一条边 / 一行行号 / 一件文件 / 一条断言）验收；手册章节结构只是颗粒度的示例呈现，**不是照抄的模板**；
  5. 每步验收底线——各步骤末尾的硬标准，不达标 = 没做完；
  6. 结束前自查表 + 完成率——完成率 = 已完成步骤 ÷ 裁定步骤，<100% 不得标记交付；范围裁剪必须开工时裁定入 log，未经裁定跳步 = 偷懒；
  6b. **状态机 · 断点续跑**——中断后第一动作是读状态表，从第一个非"完成"步骤继续，已完成不重跑；上下文将尽时落盘产物 + 宣布暂停点，禁止跳步收尾。降级只作用于工具，永不作用于步骤；
  7. 不可缩水 · 不可污染——bundle 件数基准全程不变；"篇幅/时间有限"不是缩水理由；
  8. **产物可读性**——脚本、JSON、图、文档里不得出现无解释的自造词/代号/缩写：脚本逐段注释、数据产物逐字段说明、缩写首现给全称。产物是给人看的，不是密码本；
  9. **统一产出根与命名**——全部产物收敛在 `arch-audit-output/` 一个文件夹，子目录 = 步骤号 + 英文短名：`0-bundle/`（只读快照）→ `1-scope/` → `2-graph/` → `3-cards/` → `4-architecture/` → `5-audit/` → `6-facts/` → `7-diagrams/`（图名 `NN-<类型>.mmd`）→ `8-documents/`（双文档命名 `<类型>-<项目slug>-<YYYYMMDD>.docx`），根级只放 `README.md` 导航与 `pipeline-log.md` 日志。文件名一律小写 kebab-case；产物散落或命名不合规 = 未按规交付。

## 安装

复制本目录到 `~/.zcode/skills/arch-audit-pipeline`（用户级），重启会话即被技能调度识别。

## 依赖

首选封装：Superpowers（流程骨架 + 审查门）、Cognee（持久代码知识图）、Serena（符号级查找）、import-linter（分层规则审计）。**封装是加速器不是前置条件**：任何依赖缺失时按内置降级策略（grep 建边表 + 自写 Tarjan 环检测 / 方向矩阵断言）继续，⓪→⑧ 必须完整走完——审计门不可裁剪。详见 `references/dependency-inventory.md`。

## ⑦ 用图回答问题

看懂一个项目的关键不是"画多少种图"，而是**用图回答别人（和三个月后的你自己）会问的问题**：系统由哪几块组成（容器图）、模块怎么依赖（自动生成）、一次请求走什么路（时序图）、数据什么关系（ER 图）……最小起步组合四张：容器图 + 核心链路时序图 + ER 图 + 自动生成的依赖图。**下探到哪个代码模块，那个模块就有自己的四类图**（模块架构图/模块依赖图/模块时序图/模块 ER 图，落 `7-diagrams/modules/<模块>/`）——图集覆盖率按模块计，不做一张全项目图交差。图的头号敌人是过期——能自动生成的绝不手画，手画的必须登记"过期信号"。详见 `references/diagram-playbook.md`。

## ⑧ 双文档产出

审计结论只有落成"能被两类读者各自完整看懂"的文档才算交付：**技术版**（每条断言附 file:line，字数不设上限，六步产物全部可对应到章节）+ **大白话版（教材规格）**——比喻优先、零代码出现之外，按一本入门教材的标准写：每章导读框、术语定义框、章末小结、全书术语表、参考文献列表一样不少；**专业术语首现必须附三件套：人话解释 + 英文原词 + 真实可核验的文献出处**（禁止编造文献，拿不准就写"业界通称"）。**无损汇总原则**：比喻是翻译层，不是过滤层——①-⑥ 的每条产物信息、⑦ 每张图的每个节点/边/数字，都要**无损进入三版文档**（L2 技术版原文精度 / L1 大白话教材人话 / L0 草履虫极简超短句），各自附"信息保真核对表"（产物/图 → 章节定位）逐项打勾；**⑦ 全部产出图（全局级+模块级）嵌入技术版**，大白话版含"比喻图 ↔ 技术图"对照表。三份文档计数与结论逐字一致。**三版字数都不设上限——无损优先于篇幅。**DOCX 工程规范与视觉验收硬门（渲染逐页判定，全 pass 才交付）见 `references/doc-playbook.md`。
