# 文档手册：三文档产出（⑧ 的完整方法论）

> **颗粒度声明（先读这个）**：本手册界定的是**颗粒度下限**，不是照抄的模板——章节结构只是颗粒度的示例呈现，结构可自由组织，**颗粒度不可降**。颗粒度单位 = 沙级：一条断言、一行 file:行号、一件文件、一次命令输出、一个问题计数。凡写"全录/逐件/逐条/逐行"处，缺一件即未完成。

> 审计结论只有落成"能被两类读者各自完整看懂"的文档，才算真正交付：
> **技术版**给三个月后的自己与合作者（每条断言可复查），**大白话版**给零技术背景的干系人（比喻优先、零代码出现）。
> **字数不设上限**：深度优先于篇幅——宁可慢，不可浅，禁止以"时间/篇幅有限"为由缩水。

## §A 技术版报告 · 八部分颗粒度清单

| 部分 | 必备内容 | 质量要求 |
|---|---|---|
| 执行摘要 | 审计对象与范围；**核心数字总表**（扫描文件数/边数/环数/死代码/问题分级/测试结果）；总判定（Critical 清零与否+门结论）；最重要的 3 个发现 | 全部数字可溯源到产物文件 |
| 范围框定 | 技术栈表（逐条"声明/推断"置信度）；目录职责声明-实测对照表；构建/测试命令；**未知项→解答追踪表**（①提的每个未知项在后续哪一步、以什么证据解答） | 声明与实测出入全部显式登记 |
| 静态制图 | 方法论（扫描器设计、import 风格分类、修过的 bug）；扫描总数字；模块级依赖图；**跨模块边数矩阵**（逐组列代表边 file:line）；幽灵模块双向核对全清单；路径声明证据 | 未声明件逐件定性（活/仅测试引用/死候选） |
| 分层下钻 | 每模块一张卡**全文**：职责/对外接口（符号+行号）/依赖指纹双向全列/关键依据/跨层反向引用；核心件版本史全录 | 卡数=模块数，缺一不可 |
| 架构推断 | 分层图+分层职责表；**方向审计表**（每条箭头的代码强制依据）；环检测算法与**输出原文**；死代码判定法+逐件理由；热点表+聚集评估；数据流（写入/回退）代码级序列 | 检测脚本真实运行，零环也要贴输出 |
| 架构审计 | 工具链降级记录；Critical 判零依据（逐项带运行记录）；每条 Major/Minor **完整证据链**（含行号级分类表）；改进建议 Top5（依据/影响面/落地步骤）；门结论 | 证据链细到"grep 命中逐行定性" |
| 性能报告 | ④ 核心链路实测剖面：采集命令（可复现）+ `.pstats` 原始数据存档 + 热点 TopN 表（函数+cumtime%/tottime%）+ 火焰图/热点图编号引用 + 性能发现（按影响面分级）；不可运行项目登记豁免 | **图与数字同源同一份 profile**，禁止两套数 |
| 事实校验 | 核对总表**全录**（断言→证据→结论三态）；测试实测输出原文；**反幻觉闭环案例**（证伪→回写修正的留痕） | 证伪项必须展示回写去向 |
| 附录 | 复跑指南（可复制命令+预期输出）；交付物清单（含行数）；**声明-实测差异总账**；数据面 schema；术语表；**审计局限**（如实登记：平台单一性/不可独立核验项/单快照时点；**平台单一性必须附 Windows 原生等价检测**：import 大小写静态比对 + PYTHONCASECHECK=1 复跑 + 对照实验记录，真 Linux 列为可选后续而非必需)；**图集全录——⑦ 全部产出图（全局级+模块级）逐图编号嵌入本版，一张不许少** | 局限不隐瞒；图数=图集总数可核对 |

**无损总则（§A/§B/§B2 共同）**：**三版 = 同一份无损信息的三个语言层级**——技术版（L2 原文精度超集）、大白话版（L1 教材人话超集）、草履虫版（L0 极简超集：超短句 + 绘本比喻，信息项逐项在档）。核对方式 = 两份文档各自的"信息保真核对表"（①-⑥ 产物清单 + ⑦ 图集清单 → 各自在本文档的章节定位），逐项打勾后才可交付。**两版字数都不设上限——无损是硬约束，篇幅是自由变量。**

## §B 大白话版说明书 · 九节颗粒度清单（教材规格）

> **教材规格（硬性）**：大白话版按一本入门教材的标准写，不是随手聊聊——每章开头"本章回答的问题"导读框、正文中的术语定义框、章末小结、全书术语表、文末参考文献列表，一样不能少。**专业术语首现必须附三件套：人话解释 + 英文原词 + 真实可核验的文献/教材出处**，文末以编号列表 [1][2]… 呈现，正文 [n] 引用。

| 节 | 内容 | 手法 |
|---|---|---|
| 1. 一分钟版本 | 一句话定位 + 两三个要点框 | 绿色结论框："这是一套……的系统" |
| 2. 这个项目在管什么 | 用户场景的 N 个担忧 → 逐条对策表 | 从担忧出发，不从技术出发 |
| 3. 一张图看懂全貌 | **比喻总图**（如"四层小楼+侧楼"）+ 逐层人话表（位置/名字/干什么/为什么需要） | 全篇最重的一张图，比喻必须来自受审系统自身机制 |
| 4. 核心旅程 | 一条数据/请求经过的关卡图 + "没有它会怎样"表 | 把检查机制讲成门禁/指纹/账本 |
| 5. 最讲究的设计 | 1-2 个核心设计决策的比喻（如"两个记录员互不认识"=档案室与公章分开保管）+ "审计怎么证实的"框 | 设计意图与实证证据配对出现 |
| 6. 检查/守卫机制一览 | 岗位表（名字/人话职责/工作方式） | 把工具面讲成一支队伍 |
| 7. 体检报告 | 仪表盘图（严重/中等/小问题/测试计数，绿黄配色）+ 好消息 + 中等问题人话版 + 小问题一览表 + **性能页：最耗时的三步（火焰图人话版），每个数字与技术版同源** | 问题翻成人话但**数量与分级必须与技术版一致** |
| 8. 名词小词典 | 黑话 → 人话 → 住在哪里（对应哪个模块） | 兜底零基础读者的回查需求 |
| 9. 想深入看 | 从本文到技术版的进阶路径表 + 一句话收束 | 收束句 = 项目最深的执念 |

**铁律**：大白话版**零代码出现**；每节先给一句话结论；比喻不得歪曲机制（画不准的宁可用"像……但区别是……"）。
**图对照表（硬性）**：大白话版必须含一张"比喻图 ↔ 技术图"对照表——7-diagrams 全集（全局级+模块级）逐图对应（比喻图在本版第几节 / 技术图在技术版第几章编号），读者想看精确版随时可跳；比喻版重绘图同样零代码、中文字体渲染后逐张核图。

**无损汇总三件套（硬性）**：⑴图无损——7-diagrams 全集（全局 + `modules/<模块slug>/` 每模块四类图）在本文档各有对应小节，逐节点/逐条边/逐个数字用教材人话讲清，比喻版重绘或原图+逐件讲解均可；⑵数字无损——核心数字总表的人话版逐格保留，与技术版逐字一致；⑶清单无损——⑤问题/④死代码/②幽灵/⑥核对等清单类产物逐条在列，各配一句人话，禁止合并概括。**比喻是翻译层，不是过滤层**——丢一条边、少一个数字、并掉一条清单项，都按信息丢失处理，该节未完成。

**引用纪律（术语出处的反幻觉）**：出处必须是**真实可核验**的经典文献——写得出作者 + 年份 + 标题 + 来源。可引示例：C4 模型 → Simon Brown, *Software Architecture for Developers*；append-only / 事件溯源 → Martin Fowler, *Event Sourcing*, 2005；Tarjan 强连通分量 → Tarjan, 1972, *Depth-First Search and Linear Graph Algorithms*；数据系统通论 → Kleppmann, *Designing Data-Intensive Applications*, 2017；C4 语境 → Wielanga & Snyman, *Software Architecture with C4/Carcass* 类正式出版物或官方 c4model.com。**拿不准的出处宁可不引**——写"业界通称"并解释概念即可，**禁止编造文献、编造年份页码**（与审计 ⑥ 反幻觉同源，一条假引用就毁掉整本教材的可信度）。

## §B2 草履虫版 · L0 极简颗粒度清单

> **定位**：给"完全不打算懂技术、只想知道这是啥、靠谱吗、跟我啥关系"的读者。主篇一分钟到五分钟读完；**无损三件套对 L0 同样硬性**——只是每项允许且鼓励"一句话化"。

| # | 节 | 颗粒度 |
|---|---|---|
| 1 | 一句话 | 这是什么（≤25 字）+ 一张 L0 比喻总图 |
| 2 | 它防什么 | 每个担忧一句话 + 一句对策 |
| 3 | 一次旅程 | 核心链路逐关一句话（**关卡数与技术版一致**） |
| 4 | 体检脸 | 绿黄红 + 全部关键数字逐个出现 + **最慢的一步，一句话** |
| 5 | 有啥毛病 | ⑤④ 清单逐条一句话（**条数 = 另两版**） |
| 6 | 三个词 | L0 词典 ≤5 个，各一句话 |
| 7 | 想多看 | 版本阶梯：L1 大白话版 → L2 技术版，指路 |

**L0 规则**：超短句（建议 ≤20 字/句）；每节配图优先用 L0 比喻版重绘（中文字体声明 + 逐张核图）；信息保真核对表独立成表打勾；完整解释一律指路 L1（"详见大白话版 §n"），L0 不展开、不引文献——任何概念在 L1 必有完整三件套。

## §C DOCX 工程规范（防排版缺陷，全部为实测踩坑提炼）

| 规范 | 防的坑 |
|---|---|
| 标题用内置 Heading 1/2/3 并带大纲级别 | 导航窗格/TOC 失效 |
| 表头行设 `tblHeader`（跨页重复）+ 表头单元格段落 `keep_with_next` | 续页无表头；表头孤悬页底 |
| 表格数据行与提示框行设 `cantSplit`（行内禁拆） | 行被页边拦腰拆断出残句 |
| 图片段落 `keep_with_next` 绑定图注 | 图注跨页孤立 |
| **不用强制分页**（章节自然流动，仅封面后一处分页） | 大面积空白页/近空白页 |
| 目录用 Word 原生 TOC（COM `TablesOfContents.Add` + `Update`）并回存 docx | 占位文字假目录 |
| 页脚页码（PAGE 域）、页眉文档标识 | 无页码不可引用 |
| 中文字体双写：`font.name` + `rFonts w:eastAsia` | 中文回退宋体/乱码 |
| 插图 matplotlib 需显式中文字体声明（如 Microsoft YaHei），生成后逐张人工核图 | 豆腐块/文字溢出框 |
| 工具降级序：**官方 docx skill（`documents:docx`，docx-js 创建 + OOXML 编辑，首选）** → minimax-docx（.NET OpenXML，需 dotnet SDK）→ python-docx → 手写 OpenXML；COM 转 PDF 用 Word Application SaveAs2 FileFormat=17 | 环境缺依赖时卡死 |

## §D 视觉验收硬门（全 pass 才准交付）

1. **渲染**：docx →（Word COM 导出 PDF，TOC 先 Update）→ 每页渲染 PNG；
2. **分组验收**：按 ~10 页/组分派视觉判定代理（可并行），逐页 JSON 判定（pass/fail+问题位置）；关注：表格溢出/跨页表头延续/行拆断、提示框跨页断裂、图注孤立、乱码豆腐块、异常空白页、目录是否真实条目；
3. **修复循环**：fail 项回改生成脚本 → 重新生成 → 重新渲染 → **全量复验**（分页会全局位移）；经验上 2-3 轮收敛；
4. **交付标准**：全部页 pass；目录为真实条目；三份文档（技术版/大白话版/草履虫版）结论一致。

## §E 写作纪律（两份共同）

1. **字数不设上限**：审计做了多少工作，文档就写多少——六步的每一步产物都应能在文档中找到对应章节；宁可 30 页，不可"限于篇幅从略"；
2. **诚实条款**：不可独立核验的项（如无 git 历史时的"冻结"声明）如实登记"存疑"并说明原因；局限单列一节，不隐瞒；
3. **一致性**：两份文档的问题计数、测试结果、判定结论必须逐字一致；修正一处时同步另一处；
4. **留痕**：文档自身的勘误（计数口径精化、初版失实回写）在文中显式记录，不静默改动。
5. **术语出处三件套**：专业词汇首现 = 人话解释 + 英文原词 + 真实文献出处（编号入文末参考文献）；两份文档内的自造代号、缩写同样禁止，首现处给全称 + 一句人话（执行纪律第 8 锁）。
6. **统一产出根**：三份文档落位 `<产出根>/documents/`，与 `bundle/`、`pipeline/`、`diagrams/` 同根——产物散落在产出根之外 = 未按规交付（执行纪律第 9 锁）。
7. **无损汇总**：三版都是审计信息的无损超集（L2 原文精度 / L1 教材人话 / L0 极简），信息保真核对表三份逐项打勾后才可交付；**字数三版都不设上限，无损优先于任何篇幅考虑**。
