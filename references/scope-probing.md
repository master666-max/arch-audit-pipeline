# 范围框定确定性程序（⓪ 的完整算法 · 消除"每次圈不一样"）

> **不稳定根因**：范围框定若依赖临场判断，同一项目两次执行会圈出两个边界。解药 = **确定性信号阶梯 + 可复跑探测脚本 + 量化置信度 + 覆盖率双检**——同输入必同输出（aider repo map 的成熟经验：tree-sitter 符号 + 图排序之所以稳定，因为它是算法不是感觉）。

## 1. 确定性信号阶梯（S1 → S5，逐级降级，禁止跳级）

| 信号 | 操作（命令级） | 确定性来源 |
|---|---|---|
| **S1 git index** | `git ls-files`（在候选根执行）——有 git 仓**必用**，tracked 文件清单为骨架 | 同一 commit 同一清单；untracked（`git status --short` 的 `??`）默认噪声（tmp/缓存/产物），除非用户点名 |
| **S2 包根清单** | 扫 `pyproject.toml` / `package.json` / `go.mod` / `Cargo.toml` / `*.csproj` / `SKILL.md` 等 manifest 定模块边界 | manifest 文件本身即边界声明 |
| **S3 索引/指针文件** | INDEX.md / README 逐行展开路径 | 指针可信度高于猜测（仍需 S4 验证存在性） |
| **S4 import 闭包** | 从种子文件（入口/用户点名模块）跑引用闭包：闭包内=项目内；**闭包外文件引用了闭包内文件 = 漏收信号** | 引用图是客观的（② 的 dep-edges 同源） |
| **S5 扩展名+连通团** | 扩展名枚举 + 互相引用团 | 最后手段；结果必须登记"低置信，S1-S4 不可用" |

## 2. scope-probe.py 探测程序（⓪ 必跑，可复跑可 --check）

输入：候选根目录（+可选：用户点名件、索引文件）。输出三份清单（落 `0-bundle/scope-probe-result.json`）：

```
in_scope      : [{path, confidence: high|medium|low, reason}]   # 拟收集
out_reference : [{external_file, references}]}                  # 界外文件引用了界内件 = 漏收嫌疑
excluded      : [{path, rule}]                                  # 被剔除 + 命中的规则号
```

判定规则（伪代码骨架，照此实现）：

```python
# 规则 R1（S1）：git tracked → high
# 规则 R2（S4）：非 tracked，但被 >=1 个 high 件 import/引用 → medium
# 规则 R3：类型/目录匹配（0.2 三面之一）且无剔除特征 → medium
# 规则 R4（剔除）：命中缓存/运行时db/生成产物/大二进制/封存区 → excluded（记规则）
# 规则 R5：仅名字或关键词匹配，无引用证据 → low（默认不收，进"未收清单"供裁定）
# 循环：R2 收编后重新评估其引用者（闭包传播，直到不动点）
```

**确定性校验**：脚本连续跑两遍，三份清单必须逐字节一致；不一致 = 程序有未消除的随机性（如目录遍历顺序），修程序而不是解释差异。

## 3. 覆盖率双检（⓪ 的硬验收）

- **反向覆盖 = 0**：`out_reference` 清单为空——界外没有任何文件引用界内件（非零 = 漏收，回去收编或书面说明为何不收）；
- **正向可达**：用户点名的入口/核心件全部在 `in_scope` 且置信度 ≥ medium；
- 两检结果写入 `README-BUNDLE.md`，与总件数基准同放。

## 4. 置信度三档的量化定义（① 范围框定沿用）

| 档 | 判据（满足其一） |
|---|---|
| 高 | git tracked；或被 ≥1 个高置信件引用（R2 闭包传播所得） |
| 中 | untracked 但类型/目录匹配三面之一，且无剔除特征（R3） |
| 低 | 仅名字/关键词匹配，无引用证据（R5）——**默认不收**，列入"未收清单"交用户裁定 |

① 的"声明置信度"沿用同构定义：**来源 + 一致性验证结果**两点都写（来源 ∈ {README/包清单/索引文件}；验证 = 目录结构吻合/仅声明无证据/与实测冲突），禁止裸写"高/低"。

## 5. 常见不稳定源与对策

| 漂移源 | 对策 |
|---|---|
| untracked 噪声被收（tmp/缓存/记忆文件） | S1 骨架制：默认只收 tracked；untracked 走 R3/R5 评估 |
| 索引文件过期，指向不存在的路径 | S3 展开后必须 stat 验证存在性；不存在 → 漏收清单注明"索引声明但不存在" |
| 大目录凭感觉切 | 0.3 规则先跑（du + 规则号），再人工复核——规则先行，人工只审例外 |
| 两次执行边界不同 | scope-probe 双跑一致 + 结果 JSON 留档：差异必须能 diff 出来 |
| 漏收（界外引用界内） | 反向覆盖 = 0 硬门 |
